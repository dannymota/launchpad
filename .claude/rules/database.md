# Database (D1 with Drizzle)

- **Change the schema, then generate.** Edit a file in `packages/backend/src/db/schema/`, run
  `npm run db:generate`, and commit the SQL it writes. Never write, edit or delete a file in
  `packages/backend/migrations/` by hand: a hook refuses it.
- **A migration that is committed is never edited or deleted.** It may have run on staging or in
  production. A later change to its table is a new migration.
- **One that is not committed yet is replaced, with `npm run db:redo`.** A new table changes shape
  a few times before it is right, and `npm run new:feature` generates a migration for its first
  shape at once. `db:redo` throws away the migrations git has not committed, generates one from the
  schema as it is now, and rebuilds the local database from the migrations, which resets local
  data. With nothing uncommitted it changes nothing, and it never touches a committed migration.
- **When drizzle-kit asks a question** ("created or renamed?") it needs a terminal. Without one it
  prints `Interactive prompts require a TTY terminal`, writes no migration and still exits with 0,
  so read what `npm run db:generate` printed. For a table that is not committed, `npm run db:redo`
  asks nothing. For a real rename in a committed table, either run the command in a terminal and
  answer, or make the change in two steps that ask nothing: add the new column and generate, then
  drop the old one and generate. Two steps keep none of the old column's values; the rename keeps
  them.
- **`schema/auth.ts` is generated by Better Auth** from the plugins in use
  (`npm run auth:generate -w @app/backend`). Do not edit it.
- **A table holding a person's data references `auth_user` with `onDelete: "cascade"`**, so deleting
  the account deletes it. Use `"set null"` only for records the product must keep, and say why in
  the column's comment.
- **No interactive transactions.** D1 does not have them. Writes that must succeed together go in
  one `db.batch([...])`; a check and a write that must not race go in one statement.
- **Snake case** for tables and columns. One file per feature. Money and counts are integers.
- Apply locally with `npm run db:migrate:local`. Staging and production migrations run from the
  deploy script, never by hand.
